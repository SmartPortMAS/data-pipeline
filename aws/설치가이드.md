# AWS 무인 수집기 설치가이드 (콘솔 클릭 순서 그대로)

> 작성 2026-08-04 · 담당 함현우 · 예상 소요 40분~1시간
> 목표: **EC2가 매시간 공공 API를 수집해 S3에 쌓고, 내 PC는 원할 때 내려받아 DB 적재**

## 0. 설계 한 장 (팀 보안 협의 근거)

```
[EC2 t3.micro]  매시 정각                       [내 PC]
 run_pipeline all --skip-db                 데이터_클라우드받기.bat
 (수집+전처리, DB 적재 안 함)                      │
      │  staging CSV                            │ 다운로드
      ▼                                         ▼
 ┌─────────── S3 버킷 (비공개) ────────────┐ → 로컬 PostgreSQL 적재
 │ staging/ · mart/ · raw/ · health/      │    (비밀번호는 PC에만 있음)
 └─────────────────────────────────────────┘
```

**보안 요점 (회의 "3번 보안사항 우선"에 대한 답)**
- 클라우드에 올라가는 비밀 = **공공 API 키뿐** (SSM Parameter Store 에 암호화 저장)
- **DB·Neo4j 비밀번호는 클라우드에 아예 없음** — EC2가 DB에 접속하지 않는 구조라서
- S3 버킷 비공개, EC2는 IAM 역할로만 접근 (키 파일을 EC2에 두지 않음)
- 예상 비용: t3.micro 프리티어면 **0원**, 아니면 월 1.2만원 안팎 + S3 몇백 원

---

## 1. 리전 확인 (10초)

AWS 콘솔 로그인 → 우측 상단 리전을 **아시아 태평양(서울) ap-northeast-2** 로.

## 2. S3 버킷 만들기 (3분)

1. 검색창 `S3` → **버킷 만들기**
2. 버킷 이름: `smartport-collector-hwham` (전 세계 유일해야 하므로 뒤에 본인 이니셜/숫자)
3. 나머지는 **기본값 그대로** (퍼블릭 액세스 차단 4개 전부 체크 유지) → 만들기
4. 만든 버킷 클릭 → **폴더 만들기** → 이름 `code` → 만들기

## 3. 코드 zip 업로드 (3분) — 새 서버에 우리 코드를 갖다 놓는 단계

**왜 하는가**: 7단계에서 만들 EC2는 막 산 빈 컴퓨터라 우리 수집 코드가 없다.
GitHub 에서 직접 받게 하면 비공개 레포라 로그인 토큰을 서버에 넣어야 해서 나쁘다.
대신 코드를 zip 으로 S3 에 올려두면, EC2 가 부팅하면서 스스로 가져간다.

```
[내 PC] data-pipeline.zip ─업로드→ [S3] code/ ─부팅 시 자동 다운로드→ [EC2]
```

1. zip 은 **이미 만들어져 있다**: `울산항만_프로젝트_최종본` 폴더 바로 안의
   `data-pipeline.zip` (약 292KB — .env·수집데이터·git 이력은 제외돼 있음).
   나중에 코드가 바뀌면 같은 폴더의 `aws_zip_만들기.bat` 더블클릭으로 재생성.
2. S3 콘솔 → 내 버킷 클릭 → **`code/` 폴더 이름을 클릭해 폴더 안으로 들어간다**
   (★ 버킷 루트가 아니라 code 폴더 **안**에서 업로드해야 한다)
3. **업로드** 버튼 → 탐색기에서 `data-pipeline.zip` 을 끌어다 놓기 → 맨 아래 **업로드**
4. 완료 후 목록에 `code/data-pipeline.zip` 이 보이면 성공.
   EC2 는 정확히 `s3://버킷명/code/data-pipeline.zip` 경로를 찾아가므로
   폴더 이름은 반드시 소문자 `code` 여야 한다.

## 4. API 키 등록 — SSM Parameter Store (5분)

1. 검색창 `Parameter Store` (Systems Manager 안에 있음) → **파라미터 생성**
2. 이름: `/smartport/collector-env`  (슬래시 포함 정확히)
3. 유형: **SecureString** (암호화)
4. 값: 아래 8줄을 붙여넣고 `...` 를 실제 키로 교체
   (`data-pipeline/.env` 에서 **이 8개만** 복사 — POSTGRES_·NEO4J_ 줄은 **절대 넣지 말 것**)
   ```
   UPA_SERVICE_KEY=...
   PORT_MIS_API_KEY=...
   KMA_API_KEY=...
   KMA_BUOY_AUTH_KEY=...
   KHOA_API_KEY=...
   KOSHA_MSDS_API_KEY=...
   MMAF_API_KEY=...
   AISSTREAM_API_KEY=...
   ```
5. **파라미터 생성**

## 5. IAM 역할 만들기 (5분)

1. 검색창 `IAM` → 왼쪽 **정책** → **정책 생성** → **JSON** 탭
2. `data-pipeline/aws/iam_policy.json` 내용 전체를 붙여넣고,
   안의 `BUCKET_NAME_HERE` **2곳**을 본인 버킷명으로 수정
3. 다음 → 정책 이름 `smartport-collector-policy` → 생성
4. 왼쪽 **역할** → **역할 생성** → 신뢰할 수 있는 엔터티: **AWS 서비스**,
   사용 사례: **EC2** → 다음
5. 방금 만든 `smartport-collector-policy` 체크 → 다음
6. 역할 이름 `smartport-collector-role` → 생성

## 6. 로컬용 IAM 사용자 (5분) — 내 PC가 S3를 읽기 위한 키

1. IAM → **사용자** → **사용자 생성** → 이름 `smartport-local` → 다음
2. **직접 정책 연결** → `smartport-collector-policy` 체크 → 생성
3. 사용자 클릭 → **보안 자격 증명** 탭 → **액세스 키 만들기**
   → 사용 사례 "로컬 코드" → 생성 → **Access key / Secret key 복사**
4. 내 PC `data-pipeline/.env` 맨 아래에 3줄 추가:
   ```
   AWS_ACCESS_KEY_ID=복사한키
   AWS_SECRET_ACCESS_KEY=복사한시크릿
   SMARTPORT_S3_BUCKET=본인버킷명
   ```
   (.env 는 git 에 안 올라가니 그대로 저장해도 된다)

## 7. EC2 시작 (10분)

1. 검색창 `EC2` → **인스턴스 시작**
2. 이름: `smartport-collector`
3. AMI: **Amazon Linux 2023** (기본 추천값)
4. 인스턴스 유형: **t3.micro** (프리티어면 t2.micro 도 무방)
5. 키 페어: **키 페어 없이 계속** 선택
   (SSH 접속 안 함 — 문제 생기면 인스턴스를 지우고 다시 만드는 게 더 쉽다)
6. 네트워크 설정 → 편집 → 보안그룹 규칙에서 **인바운드 규칙 전부 삭제**
   (들어오는 접속 0개 — 수집기는 나가기만 한다. 이것도 보안 포인트)
7. **고급 세부 정보** 펼치기 →
   - **IAM 인스턴스 프로파일**: `smartport-collector-role`
   - 맨 아래 **사용자 데이터**: `data-pipeline/aws/ec2_user_data.sh` 파일 내용
     전체 붙여넣기 → 상단 `BUCKET=` 한 줄을 본인 버킷명으로 수정
8. **인스턴스 시작**

## 8. 동작 확인 (10분 후)

1. S3 버킷 새로고침 → `staging/` `health/` 폴더가 생겼으면 성공
2. `health/last_run.json` 클릭 → 열기 → `"exit_code": 0` 확인
3. 내 PC에서 **`데이터_클라우드받기.bat`** 더블클릭
   → "N개 파일 수신" → 도메인별 적재 로그 → 대시보드 새로고침
4. 대시보드 헤더의 신선도 배지가 초록/노랑으로 바뀌었는지 확인

> ⚠️ 지금(8/4)은 공공데이터포털 자체가 무응답이라 staging 이 비거나 일부만
> 올 수 있다. `last_run.json` 이 생기기만 하면 수집기는 정상 — 포털이 살아나면
> 다음 정각부터 자동으로 채워진다.

## 9. 종료/정리 (제출 후)

EC2 콘솔 → 인스턴스 선택 → **인스턴스 종료(삭제)**. S3는 놔둬도 몇백 원 수준.

## 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 7단계에서 "VPC를 찾을 수 없습니다" | 계정에 서울 리전 기본 VPC 없음 | 새 탭 → VPC 콘솔 → 왼쪽 "VPC" → 작업 → **기본 VPC 생성**(무료) → EC2 탭에서 ⟳ 새로고침 후 선택. 서브넷은 아무거나, **퍼블릭 IP 자동 할당은 반드시 "활성화"** |
| .env 더블클릭 시 AnySign 오류 팝업 | 은행 보안프로그램이 낯선 확장자에 오반응 | 파일 우클릭 → 연결 프로그램 → 메모장. (4단계는 `SSM에_붙여넣을_키값.txt` 를 쓰면 .env 를 열 필요 없음) |
| 10분 지나도 S3에 아무것도 없음 | user_data 실패 | 인스턴스 종료 후 7단계 재시도 (BUCKET 오타가 90%) |
| `last_run.json` 은 있는데 staging 이 빔 | 공공데이터포털 장애 | 정상 — 포털 복구 대기 |
| bat: "SMARTPORT_S3_BUCKET 이 .env 에 없습니다" | 6-4 단계 누락 | .env 에 3줄 추가 |
| bat: AccessDenied | IAM 정책의 버킷명 오타 | 5-2 단계 재확인 |
