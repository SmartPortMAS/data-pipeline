## 절차 (약 25분, 매시 20분~45분 사이에 시작 — 정각 수집과 겹치지 않게)

### 1. zip 올리기 (2분)

zip은 이미 만들어져 있다: `울산항만_프로젝트_최종본/data-pipeline.zip` (A1+A2 포함, 검증 통과). 다시 만들려면 `python aws/make_zip.py`

> 이 업로드는 운영 배포라 Claude 가 대신 올리지 않는다(자동 모드 안전장치). 콘솔에서 직접 올린다.

AWS 콘솔 → S3 → `smartport-collector-hwham` → `code` 폴더 **안**으로 들어가기 → 업로드 → `data-pipeline.zip` 끌어다 놓기 → 업로드
(기존 파일을 덮어쓴다. 지금 올라가 있는 8/14 zip 은 `울산항만_프로젝트_최종본/data-pipeline_EC2백업_20260814.zip` 으로 받아 두었다)

### 2. EC2에 접속 (1분)

AWS 콘솔 → EC2 → 인스턴스 → 수집기 인스턴스 선택 → **연결** → **Session Manager** 탭 → 연결
(SSH·키 필요 없음. 인바운드 0 유지)

### 3. 아래를 한 줄씩 붙여넣기

```bash
sudo -i
cd /opt/smartport

# 백업 (되돌리기용)
cp -r data-pipeline backup-0917
cp collect_and_sync.sh backup-0917/collect_and_sync.sh.old

# 새 코드 받기 — .env 는 zip 에 없고 덮어쓰기라 그대로 남는다
aws s3 cp s3://smartport-collector-hwham/code/data-pipeline.zip /tmp/dp.zip
unzip -oq /tmp/dp.zip -d /opt/smartport

# 수집 잡 스크립트 교체 — 이게 있어야 다음부터 zip 자동 갱신이 된다
cp data-pipeline/aws/collect_and_sync.sh collect_and_sync.sh
chmod +x collect_and_sync.sh
aws s3api head-object --bucket smartport-collector-hwham --key code/data-pipeline.zip --query ETag --output text > code.etag

# .env 가 살아 있는지 (줄 수만 본다, 내용은 출력하지 않는다)
wc -l data-pipeline/.env
```

`wc -l` 결과가 0이 아니면 정상.

### 4. 바로 1회 실행해서 확인 (약 15분)

```bash
./collect_and_sync.sh
tail -25 logs/collect_$(date +%Y%m%d).log
ls data-pipeline/data/raw/upa | grep 'T..Z'
```

**성공 판정:**
- 로그 마지막 줄 `종료 (exit=0)`
- 마지막 명령에 `upa_vessel_position_2026091?T??Z_raw.json` 한 줄 이상

### 5. 로컬에서 확인 (다음 정시 35분 이후)

`데이터_클라우드받기.bat` 실행 → 출력에 `=== 적재: 선박위치 이력 (시각별 원본 재생) ===` 과 `선박위치 원본 N장 적재`
