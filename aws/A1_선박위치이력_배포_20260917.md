## 절차 — 인스턴스 교체 (약 40분, 새 인스턴스 시작은 매시 5~25분 사이)

> **9/17 저녁 정정 — Session Manager 로 접속해 파일을 바꾸는 방식은 쓰지 않는다.**
> ① 설치가이드 5단계의 EC2 역할(`smartport-collector-role`)에는 `smartport-collector-policy`(S3 + `ssm:GetParameter`)만 붙어 있어 Session Manager 접속 권한(`AmazonSSMManagedInstanceCore`)이 없다.
> ② zip 안의 `aws/collect_and_sync.sh` 는 CRLF 다. 손으로 `cp` 하면 cron 이 `/bin/bash^M` 로 매시 실패한다. 사용자 데이터는 `sed -i 's/\r$//'` 로 고친다.
> 그래서 8/17 재배포 안내와 같은 **인스턴스 교체**로 한다. 새 인스턴스를 먼저 확인하고 옛 것을 마지막에 종료하므로 실패해도 수집이 끊기지 않는다.

zip은 이미 만들어져 있다: `울산항만_프로젝트_최종본/data-pipeline.zip` (A1+A2 포함, 375,948 bytes). 다시 만들려면 `python aws/make_zip.py`

> S3 업로드·EC2 교체는 운영 배포라 Claude 가 대신 하지 않는다(자동 모드 안전장치, 로컬 IAM 은 읽기 전용). 콘솔에서 직접 한다.

1. **zip 올리기** — S3 → `smartport-collector-hwham` → `code` 폴더 안 → 업로드 → `data-pipeline.zip` (덮어쓰기). 옛 인스턴스에는 자동 갱신이 없어 영향 없음. 8/14 zip 은 `data-pipeline_EC2백업_20260814.zip` 으로 보관.
2. **옛 인스턴스 설정 메모** — EC2 → `smartport-collector` → 보안 탭: IAM 역할, 보안 그룹(인바운드 0 확인)
3. **새 인스턴스 시작** — 이름 `smartport-collector-0917` · Amazon Linux 2023 · t3.micro · 키 페어 없이 · **기존 보안 그룹** · IAM 인스턴스 프로파일 `smartport-collector-role` · 사용자 데이터 = `울산항만_프로젝트_최종본/EC2에_붙여넣을_사용자데이터.txt` 전문 (`aws/ec2_user_data.sh` 와 동일, `BUCKET=smartport-collector-hwham`)
4. **약 20분 대기** — 사용자 데이터가 설치 → zip → SSM 키 → cron 등록 → 1회 수집까지 한다. 첫 실행에서 `code.etag` 가 없어 "코드 갱신 감지"로 zip 을 한 번 더 받는 것은 정상.
5. **성공 판정** — S3 `raw/upa/` 에 `upa_vessel_position_YYYYMMDDTHHZ_raw.json` 이 1개 이상 + `health/last_run.json` `exit_code 0`. 로컬에서 `boto3` 읽기 전용으로도 확인 가능.
6. **옛 인스턴스 종료** — 다음 정각 전에 옛 `smartport-collector`(8월 시작) 만 종료.
